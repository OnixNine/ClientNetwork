# ClientNetwork / IrcChat

IRC-подобный чат на собственном сетевом протоколе: сервер на Kotlin (JVM) +
клиентский мод для Fabric как тестовый клиент. Общение идёт не через Minecraft,
а по отдельному TCP-протоколу поверх Netty; Minecraft-мод нужен только чтобы
подключаться к серверу из игры и видеть сообщения в чате.

> Репозиторий: <https://github.com/OnixNine/ClientNetwork>

## Из чего состоит

Проект — многомодульная Gradle-сборка (`rootProject.name = "IrcChat"`):

| Модуль | Что это | Где лежит |
|--------|---------|-----------|
| `:` (root) | сам **сервер**: авторизация, чат, модерация, консольные команды, SQLite | `src/main/kotlin`, `src/main/java/Main.java` |
| `:protocol` | общие пакеты, кодеки и шифрование; Netty перепакован в `dev.test.netty` | `protocol/src` |
| `:fabric` | **тестовый клиент** — Fabric-мод, подключается к серверу из Minecraft | `fabric/src`, см. [`fabric/README.md`](fabric/README.md) |

Сервер не зависит от Minecraft. Мод подключает протокол как fat-jar и
встраивает его прямо в свой jar, поэтому отдельный `nettyLib.jar` для запуска
мода в обычном лаунчере не нужен.

## Возможности

- **Авторизация** с выбором хеша (`Sha256` или `none`), ленивая регистрация при
  первом входе.
- **Одна активная сессия на аккаунт**: повторный вход отклоняется с кодом `202`.
- **Сессии**: соединение без авторизации рвётся через 30 с; авторизованные
  пинятся `KeepAlivePacket` каждые 10 с и отключаются, если не ответили за 30 с.
- **Чат**: рассылка всем авторизованным через событийную шину (`OnixEvents`),
  с валидацией длины, антиспам-задержкой и паттерном.
- **Модерация**: `BAN` / `MUTE` / `KICK` — временные и перманентные, с причиной,
  автором и историей.
- **Шифрование**: AES-128-GCM, ключ хранится в `config.json`, сжатие с порога 256.
- **Консольные команды**: интерактивная консоль сервера с командным фреймворком.

## Протокол

Пакеты регистрируются в `Server.createPacketRegistry()` и в клиенте должны
совпадать по id.

| id  | Пакет | Направление | Назначение |
|-----|-------|-------------|------------|
| 0   | `AuthRequestPacket`       | клиент → сервер | логин/регистрация |
| 2   | `ClientChatMessagePacket` | клиент → сервер | сообщение в чат |
| 101 | `AuthResultPacket`        | сервер → клиент | результат авторизации |
| 102 | `ChatBroadcastPacket`     | сервер → клиент | рассылка сообщения |
| 103 | `KeyExchangePacket`       | сервер → клиент | серверный AES-ключ |
| 104 | `SystemMessagePacket`     | сервер → клиент | системное уведомление (`INFO`/`WARN`/`ERROR`) |
| 105 | `KeepAlivePacket`         | сервер → клиент | пинг, клиент отвечает тем же `id` |

Коды `AuthResultPacket`:

| Код | Значение |
|-----|----------|
| 100 | вход выполнен |
| 101 | аккаунт зарегистрирован |
| 201 | неверный пароль |
| 202 | сессия уже активна на другом соединении |
| 203 | аккаунт забанен |

## Сборка и запуск

Требования: **JDK 21** (Gradle 9.8.2, Kotlin 2.2.21).

```bash
# тесты обоих модулей
./gradlew test

# сервер: собрать fat-jar с перепакованным netty
./gradlew shadowJar
# результат: build/libs/IrcChat-1.0-SNAPSHOT.jar
java -jar build/libs/IrcChat-1.0-SNAPSHOT.jar

# либо запуск Main из IDE
```

Мод-клиент:

```bash
./gradlew :fabric:runClient      # запуск клиента в dev-окружении
./gradlew :fabric:build          # mod-jar: fabric/build/libs/ircchat-test-1.0-SNAPSHOT.jar
```

Версии клиента (Minecraft 1.20.5 / Yarn / Loom и т.п.) и детали конфига —
в [`fabric/README.md`](fabric/README.md).

## Конфиг сервера

`config.json` в рабочей директории; при первом запуске создаётся автоматически,
`aes_key` генерируется, если его нет.

```json
{
  "port": 4847,
  "timeout": 20000,
  "hash": "Sha256",
  "aes_key": "<Base64 AES-128>"
}
```

| Поле | Смысл |
|------|-------|
| `port` | TCP-порт сервера |
| `timeout` | таймаут соединения (мс) |
| `hash` | алгоритм хеша пароля: `Sha256` или `none` |
| `aes_key` | AES-128-ключ (Base64) для шифрования канала |

База данных — SQLite-файл `app.db` (создаётся рядом).

## Команды (консоль сервера)

Все команды вводятся **только в консоли сервера** — оператор имеет физический
доступ к машине, поэтому отдельной системы прав нет.

| Команда | Описание |
|---------|----------|
| `/role <user> <role>` | сменить роль пользователя |
| `/kick <user> [причина]` | отключить онлайн-пользователя без записи в БД |
| `/ban <user> [срок] [причина]` | забанить (временно или навсегда) |
| `/unban <user>` | снять бан |
| `/mute <user> [срок] [причина]` | замутить |
| `/unmute <user>` | снять мут |
| `/history <user>` | вся история наказаний пользователя |
| `/plist` | список активных наказаний (алиасы `punishments`, `active`) |
| `/broadcast <текст>` | сообщение всем авторизованным |
| `/stop` | остановить сервер |

### Срок наказания

`30s`, `10m`, `2h`, `3d`, `1w`; голое число = минуты; `perm` / `permanent` /
`forever` / `never` / `-1` = навсегда.

Второй токен считается сроком только если похож на него — иначе уходит в причину:

```
/ban bob 1d спам            → срок 1 день, причина «спам»
/ban bob вёл себя плохо     → навсегда, причина «вёл себя плохо»
/mute bob 10m флуд
```

### Модерация: как хранится

Наказания лежат в таблице `punishments` (SQLite):

| Колонка | Смысл |
|---------|-------|
| `id` | номер наказания |
| `type` | `BAN` / `MUTE` |
| `username` | цель |
| `reason` | причина |
| `author` | кто выдал (обычно `CONSOLE`) |
| `issued_at` | когда выдано |
| `expires_at` | когда истекает (`NULL` = навсегда) |
| `revoked` | снято вручную |

Истечение **ленивое**: каждый запрос фильтрует
`revoked = 0 AND (expires_at IS NULL OR expires_at > now)`, поэтому фоновых
чисток нет, а временное наказание перестаёт действовать ровно в срок.

Применение:

- **Бан** — проверяется в `AuthHandler` при входе; отклоняется с кодом `203` и
  текстом причины. Онлайн-цель сразу получает системное сообщение и
  отключается.
- **Мут** — проверяется в `ChatHandler`; сообщение не уходит в рассылку, автор
  получает `WARN`.

`ban`/`mute` не требуют, чтобы аккаунт уже существовал — можно забанить
наперёд.

## Тесты

```bash
./gradlew test
```

Юнит-тесты (JUnit 5 + MockK) покрывают хеши, авторизацию, сессии/keep-alive,
парсер сроков, аргументы и сервис наказаний, чат, команды и БД. Тесты
используют собственные файлы БД (`test_users.db`, `test_punishments.db`) и не
трогают рабочий `app.db`.
